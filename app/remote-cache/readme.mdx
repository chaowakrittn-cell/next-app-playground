# !!col

- Use `use cache: remote` to store cache entries in a remote handler (e.g. Redis or KV), providing **durable, shared caching** across all server instances.
- Regular `use cache` stores entries in-memory, which works for static shell content but may have low hit rates at runtime in serverless environments.
- Most useful for data that would otherwise be re-fetched on every request, where remote caching reduces load on rate-limited APIs, slow backends, or expensive operations.

# !!col

```tsx app/remote-cache/page.tsx
async function getProductPrice(productId: string) {
  // !mark
  'use cache: remote';
  cacheTag(`product-price-${productId}`);
  const product = await db.product.find({ where: { id: productId } });
  return product.price;
}
```

### Where the cache data actually goes

<Grid>

# !!col

Writing the code is the same everywhere, but where the data is physically stored depends on where you host your app:

- **Vercel (zero config):** deploy and it just works. Vercel intercepts `use cache: remote` and routes the data into its managed Runtime Cache, stored securely in the region closest to your serverless functions.
- **Self-hosting (Docker, AWS, VPS):** Next.js doesn't know where your remote infrastructure is. You tell it by pointing at a custom cache handler (Redis, Memcached, DynamoDB, …) in your config.

# !!col

```ts next.config.ts
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  cacheComponents: true,
  cacheHandlers: {
    // Points to a file where you connect to your Redis/DB
    remote: require.resolve('./cache-handlers/redis-handler.js'),
  },
};

export default nextConfig;
```

</Grid>

**Golden rule:** because a remote cache entry is **shared across all users globally**, you must not read request-specific APIs — `cookies()`, `headers()`, or `searchParams` — inside a `use cache: remote` function. For per-user data, use `use cache: private` instead (currently experimental).

### Demo

- **Product data** is fetched with `use cache` in `getData()` - cached in the static shell.
- **Price data** is fetched with `use cache: remote` in `getProductPrice()` - stored durably in a remote cache, shared across all server instances.
- The price data function uses `cacheTag()` for targeted cache invalidation.
- Artificial delays (1s for products, 1s for prices) make caching behavior visible.
- Notice how product data loads once, while price data streams in per product, but is cached for subsequent requests.
